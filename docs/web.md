# 本机网页版

1.5.0 增加浏览器入口，继续使用桌面版的界面、业务模块、账号分区和数据目录。

## 启动

- 双击桌面「豆包工坊 网页版」，会启动本机服务并打开默认浏览器。
- 已打开桌面版时，也可以点击顶部「打开网页版」。
- 地址为 `http://127.0.0.1:17825/`。通过快捷方式或桌面按钮打开时，一次性连接链接会自动换取浏览器会话，不需要复制访问码。
- 手动输入地址的新浏览器需要本机访问码，文件在用户数据目录的 `web-access.txt`。它属于本机凭据，不要分享或提交到仓库。
- 关闭浏览器标签不会停止后台任务；退出豆包工坊会关闭本机服务。重新启动服务后，从快捷方式重新连接即可。

Windows 用户数据继续位于 `%APPDATA%\无限豆包`。升级前后的账号、Cookie、模板、草稿、任务、附件、视频和设置使用同一份数据。

## 功能对应

| 功能 | 网页版行为 |
| --- | --- |
| 账号环境、登录、代理、指纹 | 本机独立 Chromium 会话在后台运行，浏览器显示账号画面并转发鼠标、键盘、中文输入、粘贴、滚轮和素材上传。各账号继续使用原持久分区。 |
| 任务模板、模型、时长、比例、附件 | 使用原界面和同一组业务处理函数。浏览器选择的文件上传到本机数据目录，再按原逻辑生成持久附件副本，保留原文件名。 |
| 草稿箱、批量保存与发送、任务队列 | 调用原来的草稿和编排器模块，账号分配、快照、编号、停止、重试及结果取回规则保持一致。 |
| 素材库与视频预览 | 原素材目录和历史结果直接可见；浏览器通过经过授权的媒体接口播放，支持拖动进度和 Range 请求。 |
| 遮脸、图片合成、剪映草稿 | 继续由本机 Python/OpenCV/FFmpeg 和剪映集成处理，组件安装入口与桌面版共用。 |
| 文件定位、打开视频、在剪映中编辑 | 打开这台服务电脑上的文件管理器、播放器或剪映。 |
| 设置、日志、进度、更新、REST/MCP | 使用相同存储和业务函数。实时进度通过 SSE 推送；REST/MCP 原端口与鉴权不变，可单独启停，不影响网页版。 |

账号网页中的文件选择会在画面右上角提示「点击选择网页需要的素材」，点击后选择浏览器文件；也可用「上传素材」、拖放或粘贴图片。关闭某个账号标签会关闭它在网页版中的页面；刷新整个浏览器则保留后台账号页面和任务。

账号环境区传送的是本机 Chromium 的画面，操作和声音在本机执行，因此画面刷新速度与桌面原生页面有区别。素材库中的视频则由浏览器直接播放。这是需要本机服务的网页版，不是无需安装运行环境的纯静态站点。

## 连接与文件保护

网页服务只监听 `127.0.0.1`，验证 Host、Origin 和跨站请求标记。浏览器会话使用 HttpOnly、SameSite=Strict Cookie，一次性连接票据 60 秒内有效且只能兑换一次。会话过期或退出后，业务调用和账号画面不能继续访问。

媒体接口只返回业务结果或上传流程已经授权的图片、音视频，不提供任意本机路径下载。上传限制为每文件 512 MB，文件保存在独立目录，禁止上传脚本。`web-access.txt`、API token、Cookie、用户数据和发布私钥均不入库。

## 验收

运行 `npm test` 验证业务回归和新增 HTTP 登录、跨站防护、上传、媒体范围请求、事件推送及会话退出测试。

`_test/web-mode.e2e.js` 和 `_test/web-media.e2e.js` 针对独立的 `build/web-test-userdata` 数据目录及端口 17925；程序应通过 `--user-data-dir=<绝对测试目录> --web-server --web-port=17925` 启动。测试会核对数据目录，拒绝使用真实用户数据。

已验收范围包含浏览器导航、模板中文编辑与保存、附件选择、草稿快照、刷新持久化、账号画面、账号内中文与换行、鼠标点击、文件选择、真实图片与视频处理、图片合成、剪映草稿导出和视频播放。测试没有向用户的真实豆包账号提交新的生成任务；平台端生成与云电脑发送仍由原模块执行，受实际登录状态、权限、额度和网络影响。
