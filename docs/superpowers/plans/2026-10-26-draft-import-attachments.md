目标：只有当前账号草稿的正文和全部参考附件完成上传、持久保存，才计为导入成功并处理下一条。

范围：`src/orchestrator.js` 的 `saveDrafts`，`src/page/native-drafts.js` 的导入方法及对应测试；发布版本元数据。用户追加要求将模板页“直接生成视频”按钮固定禁用。保持草稿发送、自动确认、网络配置不变。

1. 用真实页面脚本的离线夹具复现按钮可用但图片延迟加载、部分上传、上传失败、正文已保存而附件缺失。
2. 传递附件清单；导入前后分别校验页面附件状态和同一原生草稿的持久附件记录。
3. 已保存或保存中草稿按原编号恢复；完整时跳过，缺失时在原草稿补齐，未知或顺序冲突时停止。停止/超时不得迟到切页。
4. 运行全部单测及含真实 Chromium 的导入回归；发送仅做已有离线回归，不触发真实发送。
5. 备份现有应用和用户数据，使用候选代码验证并修复本批账号草稿，逐条核对图片完整性与无重复。
6. 审查差异，交付本机候选版本供用户人工验收。只有用户明确确认通过，才能推送 GitHub、同步 main 并发布源码和安装包；同步检查更新服务。自动测试通过不能替代人工验收。

验收：五张素材全部就绪后才切页；重新读取草稿仍有五张有效附件；失败不计成功、不继续下一条、不新建重复草稿；网络配置及发送代码保持原样。
