# 线上50条独立验收执行计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 准备可审阅的最小线上验收候选，支持豆包-3独立50条、确认即停及原4条/旧未知保全；生产切换确认后再真实执行。

**Architecture:** Web专用批次元数据及管理员启动入口保证50份快照和原子预占；Native沿用已验证本机确认即停分支，以正式lease和原锚点返回专用终点。普通组批、计费和成片链路保持原样。

**Tech Stack:** TypeScript/SQLite/Vitest，Native JavaScript/node:test；不增加依赖。

**Spec:** ../specs/2026-10-31-online-validation50.md。

## Global Constraints

- 原4条normal草稿/批次和101旧身份标记保持；50个新任务固定账号与独立批次，不能向普通批次回退。
- 只发固定确认文字；pending/未知不重复，人工后只核验原会话；不检查视频/MP4结果。
- 只预占25积分；不能把确认回执写为真实成片完成，不改网络、并发、模型或其他板块。
- 本机候选不等于已发布、已真实50条验收；生产切换前给出具体改动和验证结果。

## Review Focus

- 相同runId重入、部分预占/进程中断、原任务快照变化均不得重复创建或重复预占。
- 普通新任务和原4条不得混入验收，目标账号有活动/未知/生成批次时拒绝开始。
- 验收回执必须有匹配的账号/批次/任务/原消息完整锚点，普通track不能借终点跳过视频核验。
- 首次确认后不得再读状态或排队；pending意图、已开始生成信号、明确拒绝各按真实状态处理。
- 遮罩/验证码在填字前后出现均先停账号，人工结束后原身份与租约仍须有效。
