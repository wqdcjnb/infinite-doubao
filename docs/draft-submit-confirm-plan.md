# 草稿完整投递与异步文字确认

目标：用户只点一次发送。定位全部选中草稿，逐条发送；每个会话独立等到生成确认提醒后回复一次“按要求生成”。不等待视频生成结束才处理下一条。

基线：上游 48d1428，1.5.2。沿用 Electron 页面自动化、当前账号绑定、持久化提交记录和现有结果取回逻辑。用户要求不改网络配置、不使用 REA。真实生成不用于自动测试。

实现与验证：

- [x] 页面识别：支持两种方案确认提醒和输入区面板，返回文字确认动作；核对参数，不点击选项。测试历史/用户消息、参数不符及重复确认。
- [x] 草稿定位：展开/滚动加载，按唯一编号及完整内容匹配。覆盖 19 条初始只显示 5 条、截断标题、延迟 1500ms 挂载及节点替换、33/50/53 条候选、缺失与重复编号。
- [x] 批量确认：已发送会话各自等待提醒，回复前持久化意图；慢会话不阻止其他会话确认；状态未知时不重复回复。覆盖乱序提醒、停止、确认中断与恢复。
- [x] 隔离验证：193 项单元测试通过；Electron 43.2.0 本地页面 19/19 定位发送，确认通过输入框发送且选项点击为 0；打包主窗口、IPC、6 个导航页面及 61 个包内源码文件与外置页面脚本一致性通过。

交付顺序：验收通过后备份安装文件和任务数据，更新本机安装版到 1.5.3；保留现有账号会话和任务，再提交并同步 GitHub，核对提交和安装文件哈希。运行时与本地素材处理组件沿用已安装版本。

本机更新核验：主界面与安装版本记录均为 1.5.3；9 个安装文件与验收产物哈希一致。6 个账号、14 条草稿、2 个模板、11 条任务记录保留；设置、账号配置、草稿和模板内容、原始提交时间均未改变。

验证边界：上述页面测试使用本地 HTML，不创建真实视频。应用重启后的既有任务继续沿用现有结果队列；中断批次的恢复尚未改为独立确认调度。真实豆包处理和成片结果仍需按任务观察。
