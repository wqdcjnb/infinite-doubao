## 2. 比对标做得更好的地方

### 2.1 指纹体检：注入到底有没有生效，能一键验

对标产品只负责「假装」，不负责「证明」。本项目新增 `src/fp-check.js` + `src/page/probe.js`：把页面里 14 个指纹面（UA、UA-CH、语言、核数、内存、webdriver、屏幕、时区、Intl、WebGL、Canvas、Audio、字体、ClientRects）读回来，与本地档案逐项比对，输出 `passed/total/failed` 与每项 `expected/actual`。

三个入口都能触发：界面「指纹体检」按钮、`POST /api/instances/:id/fp-check`、MCP `fp_check`。

这一项直接抓出了两个交付级缺陷：

1. **webview 的 `preload` 传 `file://` URL 时 Electron 43 静默不加载**——既不报 `preload-error`，也没有任何 console。表现是「UA 字符串看着改了，但 `navigator.hardwareConcurrency`、`screen`、WebGL 全是宿主真值」。修复：`will-attach-webview` 与界面 `setAttribute("preload", ...)` 一律传**磁盘绝对路径**（`src/main.js` `webviewPreloadPath()`、`renderer/app.js`）。
2. **`getHighEntropyValues` 只返回被请求的键**。真实 Chrome 无论请求什么，返回里都带 `brands/mobile/platform`；少了 `platform`，一行 `getHighEntropyValues().then(d => d.platform)` 就能判定是假浏览器。已按真实行为补齐（`src/fp-inject.js`）。

修复前后实测对比（同一台机器、同一个实例 `t1`）：

```
修 preload 路径前      PASS  8/14   （UA-CH unavailable，语言/核数/内存/屏幕/WebGL 全为宿主真值）
preload 改绝对路径后    PASS 14/14
外挂 Chrome 内核        PASS 14/14   （UA-CH 由 / 开头修正为 Windows 开头；该内核已下线，此行为存档实测）
```

`about:blank` 这类非安全上下文取不到 UA-CH 高熵值时，体检把它记成「参考项」而不是失败——不然每次本地自查都会假报漂移。

### 2.2 失败不再假成功

对标产品的 `panel_generate` 返回 jobId、`running ≠ 成功`，这套语义保留；但本项目额外堵掉了「返回值是 `{ok:false}` 却被界面当成功」的一类问题：

- `dm:jianying:draft`：分镜一帧成片都没有时，后端返回 `{ok:false, message:"没有可用的本地成片"}`，之前界面会弹「草稿已生成」。现已在上层抛错（`src/main.js`）。
- `dm:resource:download` / `POST /api/resources/download`：下载失败同理，统一转成错误提示。
- 检查更新：未配置更新源时不再傻连 `example.invalid` 然后显示「已是最新」，而是明确说「还没有配置更新源」（`src/update.js`），并把后端字段 `latest`（之前误用 `version`）显示对。

### 2.3 配置深合并

界面设置按分组下发 patch（`{orchestrator:{retryLimit:5}}`）。浅合并会把同组其它字段整体顶掉，等于「改一项重置一组」。`src/main.js` 的 `mergeDeep` 递归合并，数组整体替换。实测：改 `retryLimit` 后 `autoDownload`、`parallel` 均保持原值。

同时修掉一个更隐蔽的问题：`dm:state` 之前不返回 `settings`，而设置页读的是 `state.settings`——**用户看到的永远是默认值**，保存了也看不出来。已补 `settings: store.get().settings`。

### 2.4 一键登录、探活、额度三件事各自可解释

- 探活不靠「有没有 cookie」猜：`passport_csrf_token`、`flow_cur_user_sec_id` 在未登录访客页就存在，用它判登录会全站误判。改用 `oauth_token/sessionid/sid_tt/uid_tt/sid_guard/passport_auth_status` + 头像元素（`src/account-probe.js`）。
- 额度用尽不是报错停批，而是记「今日用尽」并进入冷却，编排器自动换下一个实例（`src/quota.js` + `src/orchestrator.js`）。
- 15s 时长这类服务端付费门控，实测结论写进配置（`upper_bound=10`、`tag_starting_duration=11`、`feature_key doubao_create_video_advanced`），不假装能出 15s。

### 2.5 剪映草稿：能按分镜整条导出

对标产品给的是「素材 → 草稿」。本项目 `src/jianying.js` 的 `filesFromStoryboard(storyboardId)` 会取同一分镜下 `status === "succeeded"` 的任务，按 `shotIndex` 升序把成片拼成时间线，一条命令出一份可编辑草稿（`POST /api/jianying/draft {storyboardId}`）。任务里也补了 `shotIndex`，所以重试、改派后镜头顺序不会乱。

### 2.6 日志与排障

`APP_HOME/logs/YYYY-MM-DD.jsonl` 按天落盘、留 7 天，事件名可 grep：`webview-attach`（webview 装配是否命中实例）、`webview-preload-alive`（注入层是否真的跑起来）、`preload-error` / `webview-preload-error`、`api-error`。上面那个 preload 缺陷就是靠这几条日志定死的。

## 4. 与报告的有意差异

| 项 | 对标产品 | 本项目 | 原因 |
| --- | --- | --- | --- |
| 运行时 | .NET 8 + WebView2 + C# WinForms | Electron 43 + 内嵌 `webview` | 一套代码同时管宿主 UI 和账号页面，且 `webview` 分区隔离天然对应「一实例一环境」 |
| 指纹注入面 | 文档描述为「注入 JS」 | 14 个可验证注入面 + 体检对账 | 注入是黑盒，必须能证明它生效 |
| 授权 | `integrity.dat` + 联网校验 + 会员档位 | 整套取消：无授权码、无会员档、无实例数/导出次数限制 | 自己用的工具，不需要再套一层壳 |
| 更新 | json 与包哈希同源 | 清单签名 + 包哈希写在签名内 | 同源可被中间人整体替换 |
| 白标 | 编译期写死 | 运行时 `brand.json` | 换皮不用重新出包 |
| 遮脸 | 报告未给实现细节 | OpenCV YuNet + ffmpeg 管道（`py/` + `src/facemask.js`） | 图片直出、视频逐帧，不落中间文件 |
| 去水印 | 列表里给个筛选，下载仍需手动选无水印版 | 全链路默认无水印：拦截时即改写地址、入库合并保留无水印版、下载先请求无水印、失败才回退并在返回值里标 `fallback` | 「下载下来的素材默认就是无水印的」，不该靠用户每次手动挑 |
| 内核 | 外挂真实 Chrome/Edge 走 CDP，靠「最像真人」 | 只有自带的内嵌 Chromium（`src/chromium.js` 已无 Chrome/Edge 探测） | 不依赖本机装没装浏览器，环境一致性不靠运气 |
| 派发默认值 | 无对应 | 并发 10 / 失败重试 3 / 每实例每日 2 条 | 按实际账号量与免费额度定的出厂值 |
| 页面增强 | 用户随便填模型与时长 | 增强开关写死开启；模型走下拉，时长按模型限幅（2.0 上限 15s、2.5 上限 30s），`src/store.js` 的 `MODEL_LIMITS` 是唯一口径，落盘时再压一次 | 选 2.0 填 30s 只会被服务端打回来，不如填的时候就拦住 |

## 5. 未覆盖 / 边界

- **授权与支付（5.19）**：按需求整体取消。授权码、会员档位、机器码绑定、实例数上限、每日导出计数全部移除；`settings.quota.perDay`（平台每日免费条数）是另一个东西，保留。
- **官方公告源**：`brand.json` 的 `links` 留空即不显示入口，没有内置官方地址。
- **第三方扩展目录**（`Extensions/dola30`）：功能已内联为页面增强脚本，不加载外部扩展，避免引入不可控代码。
- **15s 时长**：受服务端付费门控限制，实测该号只能出 10s（`upper_bound=10`），配置里如实记录，不伪造。设置页按模型档位限幅（2.0 → 最长 15s，2.5 → 30s），2.0 填超了会在保存时被压回。
- **去水印的边界**：只能改写平台自己用 URL 参数区分的「动态水印」（豆包/即梦系是 `lr=watermark` / `lv=watermark`，部分接口是 `watermark=1`）。若某条素材服务端只给了烧录进画面的版本，URL 层无可改写参数，此时如实回退带水印版并在资源卡片与下载结果里标注（`unwatermarked=false`、`fallback=true`）；不做画面级 delogo 抠除——按固定坐标糊画面会毁掉素材，位置随分辨率/构图变化，收益不抵损失。

安装包（`build/installer.mjs` + `installer/Setup.cs`）：csc 编出 WinForms 安装器 stub，把 `dist/无限豆包` 打成 zip 追加到 stub 尾部（尾 24 字节=int64 偏移 | int64 长度 | `DMINST01`），装的时候从自身尾部读 zip 解压。默认装到 `%LOCALAPPDATA%\Programs\无限豆包`，**不需要管理员权限**；写 HKCU 卸载项、桌面 + 开始菜单快捷方式；数据目录 `%APPDATA%\无限豆包` 卸载时保留（`/purge` 才删）。

```bash
"无限豆包 v1.2.0 安装包.exe"                    # 图形界面安装
"无限豆包 v1.2.0 安装包.exe" /S /D=D:\App\豆包 /NORUN   # 静默安装
"...\Programs\无限豆包\Uninstall.exe" /uninstall /quiet  # 静默卸载
```

目录规约（`src/paths.js`）：全部落在 `%APPDATA%\无限豆包\`（`store.json`、`logs/`、`drafts/`、`downloads/`、`profiles/`、`updates/`、`api-token.txt`）。`resources/webview-preload.js`、`resources/fp-inject.js`、`resources/page/`、`resources/py/`、`resources/tools/` 必须留在 asar **之外**——guest 进程读不到 asar 内的 preload。
