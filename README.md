# 豆包工坊 · 云电脑草稿提交

Windows / macOS Electron 客户端。当前源码版本为 **1.5.21**，只保留一条工作流：

**任务模板 → 云电脑草稿 → 批量提交。**

## 使用方式

1. 在「账号登录」添加并登录豆包账号。各账号继续使用独立会话，可配置代理和检查环境。
2. 在默认打开的「任务模板」填写提示词、模型、时长、比例，并添加图片或视频参考附件。
3. 将当前模板或勾选的多个模板加入「草稿箱」。模板及附件副本保存在本机，可以重复使用。
4. 在草稿箱选择保存 / 发送账号，点击「① 存入所选账号的豆包草稿」。保存成功的记录移到「已存入豆包」。
5. 在「已存入豆包」勾选草稿，点击「② 一起发送所选草稿」。固定通过工作任务云电脑，收到本条接收回执并关闭投递页后才处理下一条，不等待视频生成。
6. 在「提交记录」查看状态。已接收任务只能沿原账号、原对话继续取回；发送不明的记录保留供核对，不会自动重复发送。

账号、模板、附件、草稿和已有任务数据继续保留。草稿编号、完整正文、附件及所属账号的核对规则保持原逻辑；模板修改不改写已存草稿。移除本地草稿记录不会删除豆包网页原生草稿。「恢复中断/缺失草稿」用于恢复已确认缺失的保存记录。

客户端保留上述流程所需的停止、原对话结果取回、日志和设置。直接生成、旧分镜派发、改派、遮脸、素材库、剪映、接口面板及本机网页服务已移除。旧直接生成任务不会在重启或唤醒后自动执行，历史数据保留在原数据目录。

## 本机安装与数据

macOS 用户数据沿用 `~/Library/Application Support/无限豆包`；更换应用保留该目录。Windows 继续使用原安装与数据路径。安装器仅创建桌面客户端快捷方式，并在升级时清理旧网页版快捷方式。

源码与版本说明见 [v1.5.21 Release](https://github.com/wqdcjnb/infinite-doubao/releases/tag/v1.5.21)。安装包按 Release 实际附件提供；不同平台和架构请核对附件名称。GitHub Release 与原内网自动更新服务分别发布。

## 开发与验证

项目使用 Electron、JavaScript，`package.json` 不包含第三方运行时 npm 依赖。准备 Electron 后运行 `npm start`。

```sh
npm test
```

`_test/draft-only.test.js` 检查退役入口与旧任务隔离；`_test/draft-batch-queue.test.js` 包含精简模式下的草稿发送和原对话取回验证。完整单元测试包含独立服务器执行器的共享底层模块回归。

真实客户端隔离验收使用本地模拟豆包页面，不连接真实账号或生成视频：

```sh
DM_TEST_RUNTIME='/absolute/path/豆包工坊.app/Contents/MacOS/豆包工坊' \
  node _test/draft-only-smoke.cjs
```

该脚本使用新建的临时用户目录，验证界面、附件选择、两条原生云电脑草稿保存、逐条投递、已提交记录和旧网页 / API 服务不可启动。macOS 构建验收入口为 `_test/mac-smoke.cjs`；其余历史 `*.e2e.js` 部分针对旧功能和开发机器环境，不属于当前精简客户端的验收入口。

## 构建与源码

- `src/`：主进程、账号会话、模板、草稿及共享业务模块。
- `renderer/`：精简桌面客户端。
- `build/`、`installer/`：Windows / macOS 构建及安装脚本。
- `tools/asar.mjs`：无需第三方依赖的 ASAR 打包工具。
- `_test/`：单元测试与隔离集成验收。

Windows 构建沿用 `build/build.mjs` 和 `build/installer.mjs`；macOS 构建使用 `npm run pack:mac`。构建环境与签名配置参见相应脚本及 [更新发布说明](docs/updates.md)。

独立服务器执行端仍通过显式 `--studio-executor` 入口启动；其共用的账号窗口、页面自动化及持久化模块保留，未随桌面网页版删除。协议参见 [服务器执行器](docs/server-executor.md)。

仓库不包含账号、Cookie、Token、用户设置或素材。凭据仅在使用者本机配置。源码沿用 `UNLICENSED`，随包第三方资源保留原许可。
